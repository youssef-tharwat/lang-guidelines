# rust-guidelines: always-load files vs compiled rule card

Date: 2026-10-22. Question: does replacing the "always read all three files" skill with a
compiled rule card plus on-demand detail files cut token use without losing rule compliance?

## Protocol

- **Command:** `evals/rust-guidelines/run-ab.sh <before-skill-copy> <out>` (now `evals/run-ab.sh rust-guidelines …`) with defaults:
  3 runs per case, `--model claude-opus-5-5`, concurrency 4, judge model `haiku`
  (CLI default), `--allow-tools Write`, `--keep-temp`.
- **Harness:** Claude Code 2.1.308, `claude plugin eval`, macOS, 2026-10-22 13:46 UTC.
- **Repo base:** `30643b44ae1a776768709967057cbd5177e0933c` plus the uncommitted working tree.
- **Before arm:** the skill as it stood before the restructure. `SKILL.md` told the agent to
  always read three files. sha256:
  - `SKILL.md` 5460fb6ed87696088b3b6cf95467919a30a1e10cc54e5013730c267793e07bf7
  - `guidelines.txt` 25ff1654a770ff4fb24d573c08e48c28083b6887b095c6844abb19e37b105fa2
  - `design.md` 8bcf2ddae1cf0c5392baa9f93e4d31ff068932f1792233131a83f85ed54fb0f4
  - `patterns.md` f6cdd1d0656ebd48bf9e46a8d45cba5fa341d39a13086c6869b9112bfb2b6424
- **After arm:** `rust-guidelines/` as generated by `python3 build/compile.py rust`. The
  sha256 of the sorted per-file sha256 list is
  fec1a4eee67dbbc93aa74c065f9b75c82a3239f5dbecb127322fe74c0f90f35f.
- **No-skill arm:** the before run's ablation arm (`--ablation with-without`).
- **Cases:** `cases/` at this commit. There are five tasks, each scored by regex graders
  on the file the agent writes and an LLM rubric (weight 3).
- **Quantities:**
  - *input tokens* is the trace's final `usage`: input, cache creation and cache read
    tokens summed over all turns, so context re-read on each turn counts again.
  - *output tokens* includes thinking.
  - *Read calls* counts the agent's `Read` tool calls.
  - *cost* is the harness's per-run `costUsd`, excluding the judge.

## Reading

- **Tokens and cost:** after uses 76% fewer input tokens than before (67k vs 284k), 38%
  fewer output tokens, half the turns, and 63% less cost per task.
- **Compliance:** the same (1.00 vs 0.99). Both are near the ceiling, so this suite can
  show that compliance did not drop, but not that the card is better. The skill
  vs no-skill gap is clear (0.73 vs 0.99–1.00), driven by `config-error-type`,
  `http-client-api` and `refactor-signatures`.
- **Detail files:** the after arm never opened a `rules/` or `patterns/` file. The card
  alone carried every rule these tasks exercise. Before read 3.4 files per run on
  average, often in several partial reads because `patterns.md` exceeds one read.
- **Limits:** n = 3 per case, one model, one judge. `async-hashing` and `ffi-export` do
  not separate any arm, so they need harder variants before they can detect a
  regression.

## Re-run after the Microsoft source refresh

The Microsoft source was refreshed to upstream commit `19723b3` (90 guidelines, up from
48), which grew the card to 106 rules (about 31.8 KB). The after arm was re-run alone,
same cases and settings (`--ablation none`, 3 runs per case, `claude-opus-5-5`), at
2026-10-22 against the skill folder whose sorted per-file sha256 list hashes to
77772334c9a8829b995c43a10e5cbdf2bdb1585b1dd57524cb0a7cb44eaab60f.

No regression: the one miss was a single `config-error-type` run whose file used

variation of the first after arm (67,163).
